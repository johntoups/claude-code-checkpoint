## Session Checkpoints (all named sessions)

Every named session keeps a checkpoint so a resume never starts with "where are we". The mechanics are in the `/checkpoint` skill and three hooks; the rules are here.

- **Record and rendering.** The record is `<register>/<session-name>.md` (register: `$CHECKPOINT_REGISTER`, default `~/claude-session-register/`), committed to a private git repo. The filename equals the session name. The artifact on claude.ai is a designed HTML rendering of that file produced by `~/.claude/skills/checkpoint/render.py`, republished to the same URL. Never publish the raw Markdown. Git is the history; the artifact keeps only recent versions and its gallery omits dormant pages, so the URL lives in the register and the checkpoint header, never only in the gallery.
- **On start, resume, clear, compact.** The SessionStart hook prints the session name, checkpoint path and artifact URL. Read the checkpoint, then open the first reply with three lines: state, last session, next step. Never make me ask.
- **Unregistered session.** Do not create checkpoint files at the first prompt. After the first substantive exchange, if the topic is clear, propose a name, `/rename`, then `/checkpoint --new <name>`. The register is keyed by the `/rename` title.
- **Archive.** Finished, superseded, obsolete and resolved items are marked, not deleted; `checkpoint.py finish` moves them to `<session-name>.archive.md`, which is rendered collapsed on the same page with breadcrumbs. Read the archive only when a question needs it.
- **Wrap-up.** Phrases in `~/.claude/hooks/checkpoint-wrapup-phrases.txt` trigger a full checkpoint: file, publish, URL write-back, commit, push. `/checkpoint` does the same on demand.
- **Segue.** A prompt starting `segue:` is answered without touching topic state, then the three lines are reprinted. A quick unrelated question that arrives without the marker is treated the same way; if it grows, ask whether it should be its own session.
- **Topic change.** A rename to an unregistered name, or visible drift, gets one question: segue or new topic? A new topic gets its own checkpoint and a handoff line in the old one. A rename onto an already-registered name gets one question: rejoin or new name? Same-name sessions share one checkpoint; Decisions, Facts and Traps are append-only and Open items are reconciled, so a rejoin never clobbers the record. Never fork a checkpoint on your own judgment.
- **Content.** Facts from tool output or me, with source, separate from anything unverified. Decisions are append-only and never re-litigated after a resume. No credentials, secrets, or data your organization does not allow on claude.ai; the page is published there. API-key or cloud-provider sessions cannot publish: write the file, mark the artifact unavailable, continue.
